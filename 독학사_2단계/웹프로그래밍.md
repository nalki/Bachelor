# 1. 웹 프로그래밍의 개요

## 1.1 인터넷(Internet)과 웹(WWW)
*   **인터넷:** TCP/IP 프로토콜을 기반으로 전 세계의 컴퓨터가 연결된 거대한 네트워크망.
*   **웹 (World Wide Web):** 인터넷망 위에서 동작하는 하이퍼텍스트 정보 시스템.
*   **하이퍼텍스트(Hypertext):** 문서 내의 링크를 클릭하여 다른 문서로 즉시 이동할 수 있는 비선형적 텍스트 구조.

## 1.2 웹의 동작 원리 (Client-Server 구조)
웹 서비스는 크게 '요청하는 쪽'과 '답변하는 쪽'으로 나뉩니다.

*   **클라이언트(Client):** 웹 브라우저(Chrome, Edge 등)를 통해 서버에 정보를 요청하는 주체.
*   **서버(Server):** 웹 페이지 정보를 저장하고 있다가, 클라이언트의 요청에 응답하여 데이터를 전달하는 주체.

## 1.3 HTTP 프로토콜 (HyperText Transfer Protocol)
웹 상에서 클라이언트와 서버가 통신할 때 사용하는 약속입니다.

* **HTTP(HyperText Transfer Protocol)**: 기본적으로 텍스트 데이터를 주고받는 규약입니다.
* **HTTPS**: HTTP에 보안(SSL/TLS)이 추가된 버전입니다. 데이터가 암호화되어 전송되므로 개인정보 보호에 필수적입니다.
*   **Stateless(무상태성):** 서버는 클라이언트의 이전 상태를 기억하지 않습니다. (이를 보완하기 위해 쿠키/세션 활용)
*   **요청 메서드:**
    *   `GET`: 데이터를 조회할 때 사용 (URL에 데이터 노출).
    *   `POST`: 데이터를 서버로 전송할 때 사용 (본문에 데이터 포함, 보안 유리).
*   **주요 응답 코드:**
    *   `200`: 요청 성공.
    *   `404`: 요청한 페이지를 찾을 수 없음.
    *   `500`: 서버 내부 오류 발생.

## 1.4 정적 웹(Static)과 동적 웹(Dynamic)
*   **정적 웹:** 누가 언제 접속해도 항상 서버에 저장된 동일한 파일을 보여주는 웹. (HTML, CSS 위주)
*   **동적 웹:** 사용자의 요청, 시간, 데이터베이스 정보에 따라 서버가 실시간으로 HTML을 생성해 보여주는 웹. (JSP, PHP, ASP 등)
   
### 💻 웹 프로그래밍의 개요는 웹이 어떻게 태어났고, 우리가 브라우저에 주소를 입력했을 때 내부에서 어떤 일이 벌어지는지를 다루는 영역입니다. 기초 중의 기초지만, 시험에서는 용어 정의와 동작 원리를 묻는 문제가 자주 출제됩니다.

# 2. HTML5 (웹 구조)

## 2.1 HTML5의 특징
*   **표준화:** 특정 플러그인(ActiveX 등) 없이도 브라우저에서 멀티미디어를 재생하거나 그래픽을 구현할 수 있습니다.
*   **시맨틱 마크업(Semantic Markup):** 코드만 보고도 해당 부분이 어떤 역할을 하는지 의미를 파악할 수 있도록 태그가 구성되어 있습니다.

## 2.2 기본 문서 구조
```html
<!DOCTYPE html> <!-- 문서 형식을 HTML5로 선언 -->
<html lang="ko">
<head>
    <meta charset="UTF-8"> <!-- 인코딩 설정 -->
    <title>웹 페이지 제목</title>
</head>
<body>
    <!-- 사용자에게 보여지는 부분 -->
</body>
</html>
```

## 2.3 시맨틱 태그 (Semantic Tags)
문서의 구조를 논리적으로 나누는 태그들입니다.
*   `<header>`: 페이지나 섹션의 머리말 (로고, 메뉴 등)
*   `<nav>`: 내비게이션 링크 모음
*   `<section>`: 주제별로 연관된 콘텐츠의 묶음
*   `<article>`: 독립적으로 구분되거나 재사용 가능한 본문 (블로그 포스트, 뉴스 기사)
*   `<aside>`: 주요 콘텐츠 이외의 부가 정보 (사이드바)
*   `<footer>`: 페이지 하단의 제작 정보, 저작권, 연락처 등
```html
<header> <!-- 머리말 (로고, 메뉴) -->
    <nav>메인 메뉴</nav>
</header>

<section> <!-- 주제별 콘텐츠 묶음 -->
    <article> <!-- 독립적인 기사/포스트 -->
        <h2>학습 내용</h2>
        <p>HTML5 구조를 배우고 있습니다.</p>
    </article>
</section>

<aside> <!-- 사이드바 (광고, 링크) --></aside>

<footer> <!-- 꼬리말 (저작권, 연락처) -->
    <p>&copy; 2026 Tae-hoon. All rights reserved.</p>
</footer>
```

## 2.4 HTML5 폼(Form) 요소
사용자로부터 정보를 입력받기 위한 요소들입니다.
*   `<form>`: 입력 데이터를 서버로 전송하기 위한 범위를 지정
*   `<input>`: 다양한 타입의 입력 필드 제공 (type="text", type="password" 등)
*   **HTML5 신규 타입:** email, url, number, range, date, color 등
```html
<form action="/submit" method="post">
    아이디: <input type="text" name="id"><br>
    비밀번호: <input type="password" name="pw"><br>
    
    <!-- HTML5 추가 타입 -->
    이메일: <input type="email">
    날짜: <input type="date">
    색상: <input type="color">
    
    <button type="submit">제출</button>
</form>
```

## 2.5 멀티미디어 태그
별도의 플러그인 없이 동영상과 오디오를 재생하는 태그들입니다.
*   `<video>`: 동영상 재생 (`src`, `controls`, `autoplay` 속성 사용)
*   `<audio>`: 음악/오디오 재생
*   `<img>`: 이미지 삽입 (`src` 경로와 `alt` 대체 텍스트 필수)
```html
<!-- 이미지 -->
<img src="logo.png" alt="로고 이미지">

<!-- 비디오 -->
<video src="video.mp4" controls width="320"></video>

<!-- 오디오 -->
<audio src="audio.mp3" controls></audio>
```

### 💻 구조 태그와 입력 양식(Form)은 시험에서 코드 빈칸 채우기나 특징을 묻는 형태로 자주 등장합니다.

# 3. CSS3 (웹 디자인)

## 3.1 CSS의 개요
*   **CSS (Cascading Style Sheets):** HTML로 만든 문서의 구조에 디자인(색상, 글꼴, 배치 등)을 입히는 언어입니다.
*   **장점:** 웹 문서의 내용(HTML)과 디자인(CSS)을 분리하여 관리가 효율적입니다.
*   **적용 방식:**
    1.  **인라인(Inline):** 태그 안에 직접 작성 (`style="..."`)
    2.  **내부(Internal):** `<head>` 태그 안에 `<style>`로 작성
    3.  **외부(External):** 별도의 `.css` 파일을 만들고 `<link>` 태그로 연결 (가장 권장됨)

## 3.2 CSS 기본 문법과 선택자 (Selector)
디자인을 적용할 대상을 지정하는 규칙입니다.
```css
/* 기본 문법 */
선택자 {
    속성: 값;
    속성: 값;
}

/* 주요 선택자 */
* { } /* 전체 선택자: 모든 요소 */
h1 { } /* 태그 선택자: 특정 태그 */
.className { } /* 클래스 선택자: 중복 가능한 그룹 (HTML에서 class="...") */
#idName { } /* 아이디 선택자: 유일한 요소 (HTML에서 id="...") */
```

## 3.3 박스 모델 (Box Model)
모든 HTML 요소는 사각형 형태의 박스로 취급됩니다.

*   **Content:** 실제 내용(텍스트, 이미지)이 표시되는 영역
*   **Padding:** 테두리(Border)와 내용 사이의 안쪽 여백
*   **Border:** 요소의 테두리
*   **Margin:** 테두리 바깥쪽의 외부 여백 (다른 요소와의 간격)

## 3.4 레이아웃 및 위치 설정 (Positioning)
요소들을 화면의 원하는 곳에 배치하는 기술입니다.

*   **display 속성:**
    *   `block`: 한 줄을 독점함 (ex: div, h1, p)
    *   `inline`: 콘텐츠 크기만큼만 차지하고 옆으로 붙음 (ex: span, a)
    *   `flex`: 현대적인 레이아웃 배치 방식 (유연한 정렬)
*   **position 속성:**
    *   `static`: 기본 배치 순서
    *   `relative`: 원래 있어야 할 위치를 기준으로 이동
    *   `absolute`: 부모 요소(기준)를 기준으로 절대적인 위치에 배치
    *   `fixed`: 브라우저 화면(Viewport)에 고정되어 스크롤해도 움직이지 않음

## 3.5 텍스트 및 배경 속성
*   `color`: 글자 색상
*   `font-size`: 글자 크기
*   `font-weight`: 글자 굵기
*   `background-color`: 배경색
*   `background-image`: 배경 이미지 설정

### 💻 특히 박스 모델과 포지션(Position) 개념은 시험에서 그림과 함께 자주 등장하므로 원리를 이해해 두는 것이 중요합니다.

# 4. 자바스크립트 (JavaScript)

## 4.1 자바스크립트의 특징
*   **객체 기반의 스크립트 언어:** 웹 브라우저에서 해석되고 실행되는 인터프리터 언어입니다.
*   **동적 기능 구현:** HTML 요소의 내용을 바꾸거나, 애니메이션 효과를 주고, 서버와 데이터를 주고받는 등 정적인 웹 페이지에 생명력을 불어넣습니다.

## 4.2 기본 문법 (변수와 데이터 타입)
```javascript
// 변수 선언
let name = "Kang"; // 변수 (값 변경 가능)
const age = 20;    // 상수 (값 변경 불가능)

// 데이터 타입
let isTrue = true;      // 불리언 (Boolean)
let fruits = ["사과", "배"]; // 배열 (Array)
let user = { name: "태훈", job: "엔지니어" }; // 객체 (Object)
```

## 4.3 제어문과 함수
프로그램의 흐름을 제어하고 코드를 재사용하는 방법입니다.
```javascript
// 조건문
if (age >= 20) {
    console.log("성인입니다.");
} else {
    console.log("미성년자입니다.");
}

// 반복문 (0부터 4까지 출력)
for (let i = 0; i < 5; i++) {
    console.log(i);
}

// 함수 정의 및 호출
function sayHello(userName) {
    return "안녕하세요, " + userName + "님!";
}
console.log(sayHello("태훈"));
```

## 4.4 DOM (Document Object Model)
HTML 문서의 구조를 객체 모델로 만든 것으로, 자바스크립트를 통해 웹 페이지의 구성 요소를 직접 제어할 수 있게 합니다.

*   **요소 선택:**
    *   `document.getElementById("id")`: ID로 요소 선택
    *   `document.querySelector(".class")`: CSS 선택자로 요소 선택
*   **요소 조작:**
    *   `element.innerHTML = "내용 변경"`: 태그 내부 내용 수정
    *   `element.style.color = "red"`: CSS 스타일 수정


## 4.5 이벤트 처리 (Event Handling)
사용자의 클릭, 키보드 입력 등 특정 동작이 발생했을 때 코드가 실행되도록 하는 방식입니다.
```javascript
// 버튼 클릭 시 알림창 띄우기
const btn = document.querySelector("#myButton");

btn.addEventListener("click", function() {
    alert("버튼이 클릭되었습니다!");
});
```

## 4.6 주요 내장 객체
*   **Window:** 브라우저 창 전체를 제어하는 최상위 객체.
*   **Document:** 현재 로드된 웹 페이지 정보를 담은 객체.
*   **Math:** 수학적인 계산을 위한 객체 (`Math.random()`, `Math.floor()` 등).

### 💻 자바스크립트의 기초 문법부터 실질적으로 화면을 바꾸는 DOM 제어까지의 내용을 담았습니다. 특히 addEventListener나 getElementById 같은 메서드는 시험에서 코드를 채우는 형태로 나올 가능성이 높으니 눈여겨보세요.

# 5. XML (데이터 표현)

## 5.1 XML (Extensible Markup Language) 개요
* **정의:** 데이터를 저장하고 전달할 목적으로 만들어진 다목적 마크업 언어입니다.
* **특징:**
    * **확장성:** 사용자가 직접 태그를 정의할 수 있습니다 (HTML은 정해진 태그만 사용).
    * **자명성:** 태그명을 통해 데이터의 의미를 파약할 수 있습니다.
    * **플랫폼 독립성:** 텍스트 형식이므로 어떤 시스템에서도 읽을 수 있습니다.

## 5.2 XML 문서 구조와 규칙
```xml
<?xml version="1.0" encoding="UTF-8"?> <bookstore> <book category="programming"> <title>독학사 웹프로그래밍</title> <author>홍길동</author>
        <price>25000</price>
    </book>
</bookstore>
```
* **작성 규칙:**
    * 모든 요소는 시작 태그와 종료 태그가 반드시 쌍을 이루어야 합니다.
    * 태그명은 대소문자를 구분합니다.
    * 요소들은 올바르게 중첩되어야 합니다 (계층 구조).

## 5.3 XML의 유효성 검사 (DTD와 Schema)
XML 문서가 규칙에 맞게 작성되었는지 검사하는 방법입니다.

1.  **DTD (Document Type Definition):**
    * XML 문서의 구조를 정의하는 전통적인 방법입니다.
    * 구문이 간결하지만 XML 문법과 다르며, 데이터 타입을 세밀하게 지정하기 어렵습니다.
2.  **XML Schema (XSD):**
    * XML 기반으로 작성되어 XML 문법을 그대로 따릅니다.
    * DTD보다 복잡하지만 정교한 데이터 타입 지정이 가능하여 현재 더 많이 쓰입니다.

## 5.4 XML 파싱(Parsing) 방식 비교
프로그램이 XML 데이터를 읽어들이는 방식입니다. 시험에 매우 자주 나옵니다.

| 구분 | DOM (Document Object Model) | SAX (Simple API for XML) |
| :--- | :--- | :--- |
| **방식** | 트리(Tree) 구조로 문서 전체를 메모리에 로드 | 이벤트(Event) 발생 방식 (순차적 읽기) |
| **장점** | 데이터 탐색, 수정, 삭제가 자유로움 | 메모리 사용량이 적고 속도가 빠름 |
| **단점** | 문서가 크면 메모리 부하가 큼 | 한 번 지나간 데이터는 다시 보기 어려움 |
| **용도** | 복잡한 데이터 조작이 필요할 때 | 대용량 파일을 읽기만 할 때 |

## 5.5 JSON과 XML 비교
최근 웹에서는 XML보다 가벼운 **JSON**을 더 많이 사용합니다.
* **XML:** 데이터 크기가 크고 파싱이 상대적으로 무거움 (보안성 높음).
* **JSON:** 데이터 크기가 작고 자바스크립트와 호환성이 뛰어남 (가독성 좋음).

### 💻 XML 파트에서는 특히 DOM과 SAX의 차이점을 명확히 기억해 두시는 것이 좋습니다.

# 6. 서블릿(Servlet)과 JSP (서버 측 프로그래밍)

## 6.1 서블릿(Servlet) 개요
* **정의:** 자바를 사용하여 웹 페이지를 동적으로 생성하는 서버 측 프로그램입니다.
* **특징:** * 자바 코드 안에 HTML 코드가 들어가는 방식입니다.
    * 멀티스레딩 방식으로 동작하여 처리 효율이 높습니다.

### 서블릿의 생명 주기(Life Cycle)
서블릿은 컨테이너(Tomcat 등)에 의해 관리되며 다음 순서로 실행됩니다. (시험 단골 주제)
1.  **init():** 서블릿이 처음 메모리에 로드될 때 단 한 번 호출됩니다. (초기화)
2.  **service():** 클라이언트의 요청(GET/POST)에 따라 `doGet()`이나 `doPost()`를 호출합니다. (실제 비즈니스 로직 수행)
3.  **destroy():** 서블릿이 메모리에서 해제될 때 호출됩니다.

## 6.2 JSP (Java Server Pages) 개요
* **정의:** HTML 코드 안에 자바 코드를 삽입하여 동적인 웹 페이지를 생성하는 기술입니다.
* **특징:** 서블릿의 가독성 문제를 해결하기 위해 등장했으며, 실행 시 결국 서블릿(`.class`)으로 변환되어 실행됩니다.

## 6.3 JSP 기본 내장 객체
별도의 선언 없이 JSP 페이지에서 바로 사용할 수 있는 객체들입니다.
* **request:** 클라이언트의 요청 정보 (파라미터 등)
* **response:** 서버의 응답 정보 (페이지 이동 등)
* **session:** 클라이언트마다 고유하게 유지되는 정보 (로그인 상태 등)
* **application:** 웹 애플리케이션 전체에서 공유되는 정보
* **out:** 웹 브라우저에 데이터를 출력할 때 사용

## 6.4 쿠키(Cookie)와 세션(Session)
HTTP의 무상태성(Stateless)을 보완하여 사용자 정보를 유지하는 기술입니다.

| 구분 | 쿠키 (Cookie) | 세션 (Session) |
| :--- | :--- | :--- |
| **저장 위치** | 클라이언트(웹 브라우저) | 서버 메모리 |
| **보안성** | 상대적으로 낮음 (가로채기 쉬움) | 높음 (서버에 저장됨) |
| **용도** | 아이디 저장, 오늘 그만 보기 팝업 등 | 로그인 인증, 장바구니 등 |
| **데이터 형식** | 문자열(String) | 객체(Object) |

## 6.5 MVC 패턴 기초
* **Model:** 데이터와 비즈니스 로직 (Java Beans)
* **View:** 사용자에게 보여지는 화면 (JSP)
* **Controller:** 사용자 요청을 받아 흐름을 제어 (Servlet)
* **목적:** 유지보수를 쉽게 하기 위해 기능별로 코드를 분리하는 방식입니다.

### 💻 이 섹션은 서블릿의 생명 주기 함수 명칭과 쿠키/세션의 차이점을 묻는 문제가 정말 많이 나옵니다.

# 7. 웹 애플리케이션 보안 및 고급 기술

## 7.1 웹 보안 취약점과 대응
웹 서비스의 안전을 위협하는 요소들과 이를 막기 위한 방법입니다.

* **SQL 삽입 (SQL Injection):** 웹 페이지의 입력창에 SQL 구문을 주입하여 데이터베이스를 조작하는 공격.
    * **대응:** `PreparedStatement`를 사용하여 입력값을 쿼리와 분리합니다.
* **크로스 사이트 스크립팅 (XSS):** 게시판 등에 악성 스크립트를 삽입하여 방문자의 쿠키를 탈취하거나 페이지를 변조하는 공격.
    * **대응:** `<` 를 `&lt;` 처럼 문자로 치환(이스케이핑)하여 실행되지 않게 합니다.
* **CSRF (Cross-Site Request Forgery):** 사용자가 자신의 의지와 무관하게 공격자가 의도한 행위(비밀번호 변경 등)를 서버에 요청하게 만드는 공격.

## 7.2 데이터베이스 연동 (JDBC)
자바 프로그램(JSP/Servlet)이 데이터베이스(DB)와 통신하기 위한 표준 인터페이스입니다.

**JDBC 실행 5단계 (순서 암기 필수!):**
1.  **드라이버 로딩:** `Class.forName()`을 사용하여 DB 드라이버를 메모리에 올립니다.
2.  **데이터베이스 연결:** `DriverManager.getConnection()`으로 DB 접속 객체(Connection)를 얻습니다.
3.  **SQL 문 실행 준비:** `Statement` 또는 `PreparedStatement` 객체를 생성합니다.
4.  **SQL 문 실행:** `executeQuery()`(조회) 또는 `executeUpdate()`(변경)를 호출합니다.
5.  **자원 해제:** 사용한 모든 객체를 `close()` 메서드로 닫습니다.

## 7.3 비동기 통신 (AJAX)
* **정의:** 페이지 전체를 새로고침하지 않고도 브라우저가 서버와 데이터를 주고받아 화면 일부만 업데이트하는 기술입니다.
* **핵심:** 자바스크립트의 `XMLHttpRequest` 객체나 `fetch API`를 사용합니다.

## 7.4 웹 서비스와 REST API
* **REST (Representational State Transfer):** 웹 자원을 이름(URI)으로 구분하여 그 상태(데이터)를 주고받는 아키텍처 스타일입니다.
* **HTTP 메서드 활용:**
    * `GET`: 자원 조회
    * `POST`: 자원 생성
    * `PUT`: 자원 수정
    * `DELETE`: 자원 삭제

## 7.5 최신 웹 기술 트렌드
* **Responsive Web (반응형 웹):** 기기의 화면 크기에 따라 레이아웃이 유동적으로 변하는 웹 (Media Query 활용).
* **PWA (Progressive Web App):** 웹이면서 앱처럼 설치 가능하고 오프라인 작업이 가능한 기술.

### 💻 보안 취약점의 종류와 DB 연동 과정(JDBC)이 핵심 포인트입니다.

# HTML 주요 속성 이해: type, id, name, value

이 네 가지 속성은 웹 페이지의 데이터를 구분하고, 꾸미고, 서버로 보내는 데 핵심적인 역할을 합니다.

---

## 1. 한눈에 보는 요약 표

| 속성 | 정의 | 주된 역할 | 특징 |
| :--- | :--- | :--- | :--- |
| **type** | 요소의 종류 | 입력창의 형태(텍스트, 버튼 등)를 결정 | 어떤 데이터를 받을지 브라우저에 알림 |
| **id** | 고유 식별자 | 특정 요소 딱 하나를 지칭 (CSS/JS용) | 한 페이지에 **중복 사용 불가** (고유번호) |
| **name** | 요소의 이름 | 서버로 데이터를 보낼 때 붙이는 이름표 | 서버는 이 이름을 보고 데이터를 구분함 |
| **value** | 요소의 값 | 입력창에 담겨 있는 실제 데이터 | 초기값 설정 또는 사용자가 입력한 내용 |

---

## 2. 속성별 상세 설명

### 🎯 type (종류)
"이 입력창이 어떤 모양이어야 하는가?"를 결정합니다.
- **예시:** `text`(글자), `password`(별표 처리), `checkbox`(체크), `submit`(전송 버튼)
- **비유:** 학생의 **'전공'** (체육학인지, 음악학인지에 따라 도구가 달라짐)

### 🆔 id (고유 번호)
HTML 문서 내에서 **유일한** 별명을 붙여줍니다.
- **역할:** CSS로 특정 요소만 디자인하거나, 자바스크립트로 특정 요소를 제어할 때 사용합니다.
- **비유:** 학생의 **'학번'** (학교 전체에서 나만 가진 고유한 번호)

### 📛 name (이름표)
폼(Form)이 서버로 전송될 때, 데이터의 **키(Key)** 역할을 합니다.
- **역할:** 서버(Back-end) 개발자가 데이터를 받을 때 "name이 'userId'인 데이터가 뭐야?"라고 물어볼 때 쓰입니다.
- **비유:** 우편봉투의 **'받는 사람 성함'** (누구에게 전달할 데이터인지 표시)

### 💎 value (값)
그 요소가 실제로 가지고 있는 **'내용'**입니다.
- **역할:** 텍스트 박스에 미리 써놓을 글자나, 버튼 위에 써진 글자를 설정합니다.
- **비유:** 학생이 제출한 **'시험 답안지 내용'** (실제 데이터 알맹이)

---

## 3. 코드 예시로 이해하기

아래 코드를 보면 한 번에 이해가 됩니다.

```html
<input type="text" id="user_login_id" name="userId" value="guest123">

```

---

## 4. 꿀팁: id와 name의 결정적 차이

* **id:** **브라우저 안**에서 우리끼리(CSS/JS) 소통하기 위한 이름. (주민번호처럼 유일해야 함)
* **name:** **서버(남)**에게 보낼 때 알아보기 위한 이름. (중복 가능 - 예: 라디오 버튼은 name이 같아야 하나만 선택됨)
